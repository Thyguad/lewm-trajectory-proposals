# 第一阶段实验约定

## 问题

给定冻结的 LeWM，目标条件轨迹生成器能否提供有用的动作候选，使闭环控制在成功率或规划耗时上优于当前 CEM 设置？第二个问题是 predictor 筛选相对直接执行生成动作是否有帮助。

这两个问题不等价于证明联合生成状态具有因果正确性，也不验证跨尺度组合或替换世界模型。

## 数据与训练

- 原始 Cube HDF5，RGB224、5 维动作，`ep_len`/`ep_offset` 定义完整轨迹。
- 首轮固定种子划分 train=2000 / val=200 / test=200，支持显式排除已用于开发的轨迹。数据不足时失败。
- 每个窗口是 `z[t]` 与 `z[t+25]` 条件；监督动作是 `a[t:t+25]`，未来状态是 `z[t+5],...,z[t+25]`。窗口绝不跨 episode；含非有限动作的窗口不参与训练。
- 原始动作按完整预训练数据的固定统计归一化，与旧 predictor 输入习惯一致。生成器表征标准化只用 train 缓存拟合。
- `x_tau=(1-tau)*noise+tau*data`，学习向量场 `data-noise`；状态、动作损失各自取平均后相加。
- 仅更新生成器。encoder、projector、predictor、pred_proj 全部 eval 且不求梯度。训练阶段不调用 predictor 或 CEM。
- 验证损失使用固定窗口/噪声随机流。最佳检查点依据验证 flow loss 选择；闭环开发只使用 val；test 留到设置确定后。
- 官方 LeWM 权重是在原始数据上预训练的。这里的 held-out 只约束新生成器，不能主张整个系统对测试轨迹完全未见。
- 原始大文件只保存抽样内容指纹、结构、大小及轨迹元数据，不谎称对整个 HDF5 做过 SHA-256。权重/config 做完整 SHA-256。

## 环境与初始化

Cube 环境固定为原研究分支的 stable-worldmodel CubeEnv，依赖 MuJoCo 3.3.6 / dm-control 1.0.34 / OGBench 1.2.0。无视觉或物理扰动，单方块、224×224、非 multiview，关闭目标可视化、关闭成功自动终止，data_collection 模式。

评估器从 held-out 源轨迹中每条选一个起点，读取 qpos/qvel 并恢复到 fresh reset 的环境，目标位置/朝向取未来 25 步。qpos/qvel 不是完整历史模拟器快照；本协议不声称逐位重建原数据采集时的隐藏控制器状态。所有方法使用相同重建方式和环境种子，并核对初始像素 hash。初始渲染与源图片的 MAE 记录在日志中。

政策只看到当前图片和目标图片的表征；评价器使用位置真值计算指标。固定执行 50 个实际环境步，每执行 5 步重新规划一次。不因中途成功提前停，避免把不同执行预算混进末端比较。意外终止或截断视为运行失败，不静默减少分母。

## 规划

- CEM：每次重规划重新初始化归一化空间高斯 mean=0/std=1；300 候选，10 轮，30 精英，最小 std=0.03；每轮包含分布均值。将候选反归一化并裁剪后交给 predictor，精英用于更新高斯，执行最终均值。是当前研究 CEM 的实现约定，不宣称所有上游 CEM 逐项一致。
- Flow direct：生成 K=1，Euler NFE=8，直接执行。
- Flow ranked：同一 G 生成 K=16，NFE=8，冻结 predictor 对 16 组裁剪后的真实命令 rollout，按 `sum((z_final-z_goal)^2)` 选择。
- 每个候选有独立可复现噪声子流，因此 direct 的候选 0 与 ranked 的候选 0 对齐（仅允许批量数值舍入差）。两种方法后续状态会因决策分叉而不同。
- G 生成的中间状态不进入筛选函数；只记录选中轨迹与 predictor rollout 的 MSE 作为诊断。

## 指标和统计

主指标为第 50 步的 `distance <= 0.04m`；辅助指标为曾经成功、终点距离、初始已经成功的比例。只检查方块位置，不检查方向、抓取姿态或完整任务阶段。不要筛掉 CEM 失败案例来构造测试集。

每次决策耗时包含当前图像编码、生成和筛选；目标编码、环境执行和渲染计入回合总耗时。CUDA/MPS 在计时边界同步。报告候选转移数与实际 batched predictor 调用数，不把候选减少比例当作速度提升倍数。

同一案例和 planner seed 做配对。成功率差值的 bootstrap 以案例/源轨迹为单位聚类，避免把同一初始状态上的多个采样种子当作独立任务。planner seeds 不代表训练方差；训练方差需独立 train.seed 运行。

默认设置不是等时间或等世界模型调用数比较。只有在明确控制计算预算的后续运行中，才能声称等计算量收益。

## 决策

先以 val 小规模检查接口与闭环失败方式。候选生成损失下降不自动证明闭环收益。若 ranked 有收益，进一步区分质量、采样数量和速度的贡献，再决定是否研究轨迹组合；若只有速度收益，应按速度—质量权衡报告。测试结果不佳同样保留原始日志。
